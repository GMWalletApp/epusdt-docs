# 販売と納品 {#commerce-and-fulfillment}

GMShop Edgeは、単一のシステムで、カタログ、チェックアウト、在庫管理、権利管理、サプライヤーからの発注、履行、および販売後のサポート機能を統合します。

## 製品および権利 {#products-and-entitlements}

製品の種類は：

- `stock`: 暗号化して事前登録したテキスト（ライセンスキー、アカウント、アクティベーションコード、認証情報など）をアトミックに割り当てます。
- `download`: 非公開ファイルへのアクセス権を制限付きで付与します。
- `automation`: デプロイ、スクリプト、リソースのプロビジョニング、ビルドワークフローを実行します。成果物の扱いは `none | optional | required` で指定します。

権利は、永続的なもの、期間付きのもの、限定的なもの、無制限のもの、無料のもの、一回のみのもの、または顧客による更新のものを指します。注文は、入力定義、価格、権利、履行、および自動化の不変のキャプチャを保持します。

## 顧客の所有権と、経済的行動（ウォレット） {#customer-ownership-and-wallet}

登録された注文は、Better Auth ユーザーを直接参照します。ゲスト注文は、確認済みの決済メールを保持し、一致する確認済みのアカウントによって回収されます。シャドウ顧客テーブルは作成されません。

各アカウントは、ストアのウォレットを使用できます。この記録は、小単位の整数での変動を記録し、浮動小数点を使用せずに、支払い、払い戻し、および管理の調整をサポートします。

## サプライヤー調達 {#supplier-sourcing}

GMShop Edgeは以下の機能をサポートします：

- ACG `3.5.5` V4 Open API
- Dujiao Next `v1.3.1`
- ネイティブなGMShop Edgeのサプライヤー間連携。

ネイティブのサプライヤーAPIは、管理者によって作成されたAPIキー、認証されたHTTPエンドポイント、カタログへのアクセス、およびidempotentな注文操作を利用します。別のGMShop Edgeインスタンスは、その組み込みのサプライヤーアダプターを使用して、製品を同期し、このAPIを通じて注文を処理することができます。

各プロバイダー/API ソースにおいては、対象となるアカウントは平等な優先順位を持つプールを形成します。カタログの同期、購買、コールバック/調整、および配送は、堅牢な状態機械と、統合された配送記録パイプラインを通じて行われます。

## 実現と運用 {#fulfillment-and-operations}

キューとスケジュールされた作業が、在庫配分、サプライヤーの調達、プライベートダウンロードの配信、自動化されたタスク、通知、払い戻し、再試行、有効期限、キャンセル、保持、および手動での復元を処理します。クライアントからの入力による、プライベートオブジェクトキーの選択は行いません。

地域での受け入れテストについて：

```bash
bun run seed:local
```

このコマンドはローカルでのみ有効であり、同じ操作を何度実行しても同じ結果が得られます。`.example.invalid` のドメインを持つ無効なサプライヤーアカウントを作成しますが、認証情報が変更されるか、アカウントが明示的に有効になるまで、実際のアップストリームとの通信は行えません。
