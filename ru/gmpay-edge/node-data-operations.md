# Управление данными в Bun {#bun-data-operations}

Развертывание Bun сохраняет свою базу данных SQLite в файле `$GMPAY_DATA_DIR/gmpay.sqlite`, а приватные объекты – в каталоге `$GMPAY_DATA_DIR/objects`.  CLI и сервер приложений работают с использованием Bun и его драйвера SQLite.

## Резервное копирование и восстановление {#backup-and-restore}

Прекратите работу контейнера GMPay Edge перед созданием резервной копии или восстановлением, чтобы база данных и файлы объектов оставались в одном и том же логическом моменте времени.

```bash
GMPAY_DATA_DIR=/srv/gmpay bun run data -- backup --output /srv/backups/gmpay-backup
GMPAY_DATA_DIR=/srv/gmpay-restored bun run data -- restore --input /srv/backups/gmpay-backup
```

Опубликованное изображение содержит тот же CLI. После остановки сервиса, смонтируйте внешний каталог резервных копий и выполните:

```bash
docker compose stop gmpay-edge
docker compose run --rm --no-deps \
  --volume "$PWD/backups:/backups" \
  gmpay-edge bun run data -- backup --output /backups/gmpay-backup
```

Путь к исходным или выходным данным всегда указывается явно. Сохраняйте копию вне каталога данных. Восстановление возможно только в новый или пустой каталог. Все файлы сверяются с манифестом; при восстановлении также проверяются целостность SQLite, внешние ключи и контрольные суммы миграций.

Резервные копии содержат учетные данные, пользовательские данные, записи о платежах и личные загрузки. Шифруйте их при хранении, ограничьте доступ и регулярно проверяйте возможность восстановления.

## Импортировать экспорт Cloudflare {#import-a-cloudflare-export}

Экспортируйте D1 в формате SQL и объекты R2 в локальную директорию, используя относительные пути, соответствующие исходным ключам объектов. Затем импортируйте в новую или пустую директорию Bun.

```bash
wrangler d1 export DB --remote --output ./d1-export.sql
GMPAY_DATA_DIR=/srv/gmpay bun run data -- import-cloudflare \
  --d1-sql ./d1-export.sql \
  --r2-dir ./r2-export \
  --r2-manifest ./r2-metadata.json
```

`--r2-dir` является необязательным параметром, когда у экземпляра нет объектов. `--r2-manifest` также является необязательным параметром, но требует `--r2-dir`; он используется для сохранения HTTP и пользовательских метаданных R2. Это JSON-объект, индексированный по исходному ключу объекта R2.

```json
{
  "evidence/receipt.txt": {
    "httpMetadata": {
      "contentType": "text/plain; charset=utf-8",
      "cacheExpiry": "2026-09-01T00:00:00.000Z"
    },
    "customMetadata": { "orderId": "order-123" }
  }
}
```

Поддерживаются следующие HTTP-поля: `contentType`, `contentLanguage`, `contentDisposition`, `contentEncoding`, `cacheControl` и ISO 8601 `cacheExpiry`. Неподдерживаемые поля, произвольные метаданные, отличные от строк, и ключи манифеста без соответствующего экспортированного объекта, отклоняются. Без этого "sidecar", байты и ключи объекта импортируются, но метаданные R2 не могут быть восстановлены.

Импорт проверяет, что все миграции репозитория присутствуют в экспорте D1, регистрирует их контрольные суммы для запуска миграций Bun, проверяет внешние ключи и преобразует пути ключей R2 в структуру приватных объектов с хешированием. Он отклоняет пустой целевой объект, поэтому неудачный или повторяющийся импорт не может перезаписать существующую инстанцию.
