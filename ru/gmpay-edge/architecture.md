# Архитектура {#architecture}

GMPay Edge работает в одном Worker или контейнере Bun/Nitro. Обе среды предоставляют одинаковые интерфейсы и используют общее ядро заказов и платежей. Различаются только адаптеры инфраструктуры.

## Интерфейсы сервиса {#product-surfaces}

- Приложения продавцов обращаются к API GMPay или к интерфейсу, совместимому с EPay.
- Покупатели оплачивают заказ на размещённой платёжной странице.
- Операторы используют `/admin`.
- Пользователи Telegram общаются через настроенного бота.

## Сервисы среды выполнения {#runtime-services}

| Возможность | Cloudflare Workers | Bun/Nitro Docker |
| --- | --- | --- |
| База данных | D1 | SQLite в каталоге `GMPAY_DATA_DIR` |
| Кеш | KV | Локальный кеш среды выполнения |
| Закрытые объекты | R2 | Постоянное локальное хранилище объектов |
| Фоновые задачи | Cloudflare Queues | Локальные очереди с сохранением данных |
| Планирование задач | Cron Triggers | Планировщик Bun |

Директория данных Bun также содержит загруженные файлы и стабильное состояние очереди. Ее необходимо монтировать на постоянный том и включать в резервное копирование.

## Привязки Cloudflare {#cloudflare-bindings}

| Привязка | Продукт Cloudflare | Назначение |
| --- | --- | --- |
| `DB` | D1 | Надежные данные об обработке платежей, авторизации и доставке. |
| `CACHE` | KV | Краткосрочные, проверенные кэши и дополнительная телеметрия. |
| `FILES` | R2 | Документы и отчеты, подтверждающие использование частных платежных систем, а также сгенерированные экспортные данные. |
| `PAYMENT_QUEUE` | Очереди | Сканирование асинхронных платежей |
| `WEBHOOK_QUEUE` | Очереди | Доставка Webhook для интернет-магазина (асинхронная) |

## Фоновые задачи {#background-work}

Очереди и планировщики, адаптированные под конкретное время выполнения, переносят сканирование платежей и повторные запросы Webhook за пределы синхронных запросов. Они также обрабатывают истечение срока платежей, очистку, проверку состояния соединений и синхронизацию скорости.

Доставка вебхуков использует надежный "выходной" механизм с историей повторных попыток, возможностью ручной повторной попытки и данными аудита на любом этапе.

## Модель данных и безопасности {#data-and-security-model}

- В выбранной среде выполнения основным источником данных служит D1 или SQLite.
- Кэш и приватное хранилище используют адаптеры выбранного времени выполнения.
- Адаптеры оплаты являются только для чтения.
- Администрация использует Better Auth, TOTP и динамическую многоролевую RBAC.

## Границы протоколов {#protocol-boundaries}

Для подписей GMPay используется **HMAC-SHA256**, а интерфейс совместимости с EPay сохраняет **MD5**. Исходящие уведомления подписываются в формате исходного протокола.
