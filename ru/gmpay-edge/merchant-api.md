# API продавца {#merchant-api}

GMPay — основной протокол для продавцов. EPay — адаптер совместимости, который использует те же учётные данные, службу заказов, правила идемпотентности, переходы состояний, кассу, запросы и обработку уведомлений.

Для авторитетных полей и значений статуса, используйте страницу `/docs` развернутой инстанции или отслеживаемый в репозитории OpenAPI контракт: [`public/openapi.yaml`](https://github.com/GMWalletApp/gmpay-edge/blob/main/public/openapi.yaml).

## Подписи GMPay {#gmpay-signatures}

GMPay запросы включают числовой `pid` и строгую HMAC-SHA256 `signature`.

Как подписать запрос

1. Исключите поле `signature` и пустые значения.
2. Сортируйте поля по порядку ASCII.
3. Соедините пары `key=value` через `&`.
4. Используйте ключ HMAC «Secret».
5. Вычислите HMAC-SHA256 и запишите результат шестнадцатеричными символами в нижнем регистре.

## Создание заказа {#create-order}

<span class="api-route"><b>POST</b> <code>/payments/gmpay/v1/order/create-transaction</code></span>

Повторное использование существующего `order_id` не создает второй заказ. Отсутствие как `token`, так и `network` создает заказ, который можно выбрать; GMPay Edge не автоматически устанавливает его значение как TRON.

## Получение заказа {#query-order}

<span class="api-route"><b>GET</b> <code>/payments/gmpay/v1/order/query</code></span>

Предоставьте либо `trade_id`, либо `order_id`, а затем подпишите запрос с теми же учетными данными. Учетные данные позволяют запрашивать только те заказы, которые были созданы пользователем.

## Получение уведомлений {#receive-callbacks}

Торговец предоставляет `notify_url` при создании заказа. Цели обратного вызова должны передавать экземпляр SSRF и политику безопасности.

События, которые были обработаны, имеют детерминированные сигнатуры, сохранение попыток, ограниченное количество повторных попыток, и проверенный ручной путь повторных попыток. Обработчики должны проверять сигнатуру, обрабатывать дублирующиеся события идентично, и подтверждать только после сохранения локального состояния.

После успешной обработки уведомления GMPay верните HTTP 200 и текст `ok`.

## Совместимость с EPay {#epay-compatibility}

Совместимость с EPay использует одни и те же учетные данные и процесс обработки заказов, но сохраняет старую систему проверки EPay MD5 для входящих запросов и совместимых ответов.
