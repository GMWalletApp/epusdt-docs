# API поставщика {#native-supplier-api}

GMShop Edge может выступать в качестве поставщика цифровых товаров для другого экземпляра GMShop Edge. Встроенный протокол предоставляет операции каталога, оформления заказа, оплаты и пополнения кошелька через `/api/v1/supplier/*`. Это протокол для поставки в торговой точке, а не API платежного шлюза.

## Активировать и предоставить учетные данные. {#enable-and-issue-credentials}

Активируйте API поставщика в настройках администратора, а затем создайте API-ключ для учетной записи клиента, который будет совершать покупки в этом магазине. Секрет отображается только при создании и хранится зашифрованным. Ключи могут быть отменены, а также можно указать необязательный "разрешенный" Origin для ограничений места, куда будут отправляться ответы о выполнении заказов.

Конфигурация GMShop Edge выбирает адаптер поставщика `gmshop_edge` и сохраняет идентификатор и секрет полученного ключа в своей зашифрованной конфигурации выполнения.

## Подпись запросов {#request-signing}

Каждый запрос должен использовать HTTPS без указания порта и отправлять:

- `GMShop-Edge-Api-Key`: идентификатор ключа.
- `GMShop-Edge-Timestamp`: 10-значный Unix-временной штамп в секундах.
- `GMShop-Edge-Nonce`: уникальное значение, состоящее из 16-100 букв и цифр, а также дефисов.
- `GMShop-Edge-Signature`: строгая HMAC-SHA256 шестнадцатеричная сумма.

Создайте payload для подписи, объединив следующие значения с помощью символов новой строки:

```text
UPPERCASE_HTTP_METHOD
PATH_WITH_RAW_QUERY
UNIX_TIMESTAMP
NONCE
SHA256_HEX_OF_RAW_BODY
```

Вычислите HMAC-SHA256 для этих данных с выданным секретом API. Сервер допускает расхождение времени до 60 секунд и записывает каждый nonce для защиты от повторов. Повторное использование nonce вызывает конфликт. Ограничения — 120 запросов в минуту на ключ и 300 на пользователя.

## Методы API {#endpoints}

| Операция | HTTP | Путь |
| --- | --- | --- |
| Тестовые учётные данные | POST | `/api/v1/supplier/ping` |
| Получить список категорий | GET | `/api/v1/supplier/categories` |
| Получить список товаров | GET | `/api/v1/supplier/products` |
| Получить сведения о товаре | GET | `/api/v1/supplier/products/{productId}` |
| Создать заказ | POST | `/api/v1/supplier/orders` |
| Получить заказ | GET | `/api/v1/supplier/orders/{orderId}` |
| Отменить заказ | POST | `/api/v1/supplier/orders/{orderId}/cancel` |
| Получить список каналов оплаты | GET | `/api/v1/supplier/payment-channels` |
| Создать запрос на пополнение | POST | `/api/v1/supplier/topups` |
| Получить сведения о пополнении | GET | `/api/v1/supplier/topups/{id}` |

Создание заказов и операции по пополнению баланса являются идемпотентными. При повторной обработке неопределенного запроса, сохраняйте эту идемпотентность; не создавайте новый заказ у поставщика только потому, что клиент превысил лимит времени.

## Справочник API {#api-reference}

Развернутый экземпляр перенаправляет `/openapi` на его интерактивную справочную документацию. Репозиторий также публикует полный [OpenAPI YAML](https://github.com/GMWalletApp/gmshop-edge/blob/main/public/openapi.yaml), охватывающий аутентификацию, обработку заказов, ответы от поставщиков, администрирование, поддержку через веб-интерфейс и протокол для непосредственного взаимодействия с поставщиками.
