# Интеграция с EPay через перенаправление {#epay-compatible-integration-redirect-checkout}

Используйте этот сценарий только тогда, когда внешней системе нужен заказ с перенаправлением в формате EPay.

## Маршрут {#route}

```text
GET /payments/epay/v1/order/create-transaction/submit.php
POST /payments/epay/v1/order/create-transaction/submit.php
```

## Требование о наличии торгового удостоверения {#merchant-credential-requirement}

Для проверки входящих запросов устаревшие переменные окружения `epay_pid` и `epay_key` **не используются**.

Текущий вариант делает это вместо этого:

1. Прочитать входящий `pid`
2. Найдите строку `api_keys`, которая включена, с указанным PID.
3. Проверьте `sign` с использованием `secret_key` этой строки.
4. Применить опциональную проверку списка разрешенных IP-адресов

## Обязательные поля запроса {#required-incoming-fields}

- `pid`
- `money`
- `out_trade_no`
- `notify_url`
- `sign`

Необязательные общие поля

- `return_url`
- `name`
- `type`
- `token`
- `network`
- `currency`
- `sign_type`

`type` теперь поддерживает два формата:

- `alipay` — значение для совместимости. Сначала используются явно заданные параметры запроса `token` и `network`, затем — значения EPay по умолчанию из настроек администратора.
- Селектор `token.network`, например, `usdt.tron`, принимается только в том случае, когда данная пара токена/сети поддерживается.  Действительный селектор переопределяет `token`, `network`, `epay.default_token` и `epay.default_network`.

Другие непустые значения `type` отклоняются как недопустимые параметры. Выбранное или совместимое значение `type` сохраняется в порядке для последующих обратных вызовов/уведомлений EPay.

## Значения EPay по умолчанию {#epay-defaults}

После проверки подписи, текущий источник создает внутренний общий payload заказа с настройками администратора:

- `epay.default_token`
- `epay.default_currency`
- `epay.default_network`

Порядок решения для EPay submit.php:

1. Поддерживается селектор `type=token.network`, если он предоставлен.
2. Явный запрос параметров `token` / `network`
3. Настройки администратора `epay.default_token` / `epay.default_network`
4. Если и токен, и сеть все еще пусты, создать заготовленный заказ со статусом «`4`» для этапа выбора кассира.

Валюта является независимой: запрос `currency` → `epay.default_currency` → `cny`.

## Действия при успехе {#success-behavior}

Относительно успеха, конечный адрес перенаправляет браузер на:

```text
/pay/checkout-counter/{trade_id}
```

В текущей реализации, этот путь теперь является перенаправлением для SPA-приложения кассира. Данные страницы оформления заказа передаются через:

```text
/pay/checkout-counter-resp/{trade_id}
```


## Прямой выбор токенов/сетей {#direct-token-network-choices}

Для списков методов оплаты "New API" в "upstream", предоставьте отдельные опции, у которых `type` соответствует поддерживаемому `token.network` селектору. Например, `usdt.tron` создает прямой ордер на TRON USDT, а `usdt.binance` создает ордер на Binance/BSC USDT, когда этот актив включен.

Пример списка методов "upstream":

```json
[
  { "color": "rgba(var(--semi-blue-5), 1)", "name": "GM Pay", "type": "custom1" },
  { "color": "rgba(var(--semi-blue-5), 1)", "name": "GM Pay usdt.binance", "type": "usdt.binance" },
  { "color": "rgba(var(--semi-blue-5), 1)", "name": "GM Pay usdt.tron", "type": "usdt.tron" }
]
```

`custom1` — общее имя опции во внешней системе. Не передавайте его как есть в EPay submit.php. Опустите `type`, укажите `type=alipay` или используйте допустимый селектор, например `usdt.tron`.

## Проверка уведомлений {#callback-verification}

Если в созданном заказе указано `payment_type = Epay`, Worker впоследствии вызывает `notify_url` с параметрами EPay и подписывает их **тем же ключом продавца `secret_key`**.

Вызов `type` использует ранее сохраненный тип запроса. Это означает, что он возвращает либо `alipay`, либо принятый селектор, например, `usdt.tron`. Если запрос не содержал `type`, внешние вызовы по умолчанию возвращают `alipay` для обеспечения совместимости.

Не проверяйте эти звонки, используя старый, независимый `epay_key`.
