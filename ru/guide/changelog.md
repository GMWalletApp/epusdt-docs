# История версий {#release-notes}

## v2.1.1 {#v2-1-1}

2026-11-21 · [Примечания к выпуску](https://github.com/GMWalletApp/epusdt/releases/tag/v2.1.1)

EPUSDT теперь использует только SQLite. Пользователи SQLite могут сохранить свои настройки и базы данных. Если вы используете MySQL или PostgreSQL, создайте резервную копию, перенесите и проверьте данные до обновления.

## v2.1.0 {#v2-1-0}

2026-11-21 · [Примечания к выпуску](https://github.com/GMWalletApp/epusdt/releases/tag/v2.1.0)

- Встроенный ChainScanner продолжает сканирование с сохранённой позиции и повторно запрашивает пропущенные блоки. Строгая проверка добавляет состояния подтверждения и ручной проверки.
- Восемь новых сетей прямых платежей увеличивают общий показатель до 16. Также в процессе оформления заказа поддерживается вывод средств через OKX OnchainOS на X Layer, а также опциональное напоминание об комиссии за вывод средств на бирже.
- Исправлены проблемы с блокировкой SQLite при конфликтах и освобождение зарезервированной суммы более нового заказа, вызванное истекшим заказом. Пользователи, обновляющиеся с версии v2.0.0, должны перенести свои данные перед повторной созданием контейнера.

## v2.0.0 {#v2-0-0}

- Тег версии: `v2.0.0`
- Дата публикации: `2026-07-23T06:04:47Z`
- Официальное описание версии: `Breaking change for GMPay integrations: GMPay signatures changed from MD5 to HMAC-SHA256`
- Полный список изменений: `https://github.com/GMWalletApp/epusdt/compare/v1.0.10...v2.0.0`

### Изменения для пользователей {#user-visible-changes}

- **Несовместимое изменение подписи GMPay**: запросы и уведомления теперь подписываются HMAC-SHA256 с ключом продавца `secret_key`. Старые клиенты GMPay на MD5 будут получать `401 Unauthorized` до обновления.
- Для запросов и уведомлений EPay ничего не меняется: они используют MD5 и поля `sign` и `sign_type`.
- Теперь данные для инициализации кассира включают `server_time`, что позволяет клиентам рассчитывать время до наступления события относительно времени сервера, вместо того чтобы полагаться на часы браузера.
- В `sdk/python/gmpay_create_order.py` добавлен пример создания заказа GMPay на Python без сторонних библиотек.
- Процесс восстановления платежей EVM был улучшен, что позволяет более надежно восстанавливать заблокированные временные слоты сканера.

### Внесение изменений в развертывание и конфигурацию {#deployment-and-configuration-changes}

- Обновите список клиентов GMPay перед внедрением v2.0.0: исключите параметр `signature`, исключите пустые значения, отсортируйте параметры по порядку ASCII, объедините их в формате `key=value&key=value`, а затем рассчитайте нижний регистр шестнадцаричный HMAC-SHA256 с использованием `secret_key`.
- Настройки скорости теперь поддерживают `rate.mode=fixed|auto` и `rate.cache_ttl_seconds` в диапазоне от `10` до `86400` секунд. Режим "fixed" использует `rate.forced_rate_list`, а режим "auto" получает `rate.api_url` и сохраняет долгосрочный кеш.
- Автоматическая оценка обновлений сохраняет предыдущие успешные курсы валют в случае неполного ответа от провайдера и продолжает использовать последнюю сохраненную кэш-память, если обновления или сохранение не удаются.

### Изменения API {#api-changes}

- Маршрут `POST /payments/gmpay/v1/order/create-transaction` теперь проверяет `signature` GMPay с помощью HMAC-SHA256 вместо MD5.
- Все запросы от торговых партнеров (GMPay) должны быть проверены в соответствии с тем же правилом "canonical-параметра" HMAC-SHA256.
- В ответе `GET /pay/checkout-counter-resp/{trade_id}` теперь есть поле `server_time`.
- Админ-API добавляют `GET /admin/api/v1/settings/rate/status` и `POST /admin/api/v1/settings/rate/refresh` для проверки кэша тарифов и принудительного обновления.

- Релиз на GitHub `v2.0.0`
- PR `#104` (разработка, слияние) и PR `#99` (восстановление восстановления EVM).
- Коммиты: `44d90b6` (восстановление пропущенных данных EVM), `f086d8b` (поле кассы `server_time`), `3dc8ab0` (автоматические курсы с постоянным резервным кешем), `58141cd` (подписи GMPay HMAC-SHA256), `2353d85` (пример SDK GMPay для Python).

## v1.0.10 {#v1-0-10}

- Тег версии: `v1.0.10`
- Дата публикации: `2026-07-10T13:24:42Z`
- Официальное описание версии: `Allow admin to mark expired on-chain orders as paid and seed rates`
- Полный список изменений: `https://github.com/GMWalletApp/epusdt/compare/v1.0.9...v1.0.10`

### Изменения для пользователей {#user-visible-changes-1}

- После проверки переданного хеша транзакции администратор может вручную отметить **просроченный ончейн-заказ** как оплаченный. Публичный метод отправки хеша по-прежнему принимает только заказы в ожидании. Просроченные заказы и заказы OkPay или других провайдеров отклоняются.
- В системе предусмотрена автоматическая установка стандартного курса для конвертации стабильной криптовалюты CNY: `cny.usdt` и `cny.usdc` по умолчанию устанавливаются равными `0.14705882352941177`.
- Пустой `rate.forced_rate_list` восстанавливается до стандартного CNY стабильного токена по умолчанию после обновления настроек или удаления настройки; любой непустой пользовательский JSON остается в собственности пользователя и не объединяется или перезаписывается.
- `rate.api_url` теперь необязательный параметр; если он указан, он по-прежнему должен быть общедоступным HTTP/HTTPS URL.

### Внесение изменений в развертывание и конфигурацию {#deployment-and-configuration-changes-1}

- `epctl upgrade` теперь требует наличия существующего `/opt/epusdt/.env`, поэтому обновление больше не создает новый конфигурационный файл. Сначала запустите `install` на чистой машине.
- Прямая команда `epctl upgrade` заменяет файлы релизов и автоматически перезапускает `epusdt`. Используйте `--no-restart`, чтобы загрузить файлы без перезапуска, или `--prompt-restart`, чтобы запросить перезапуск в интерактивной терминале.
- Обновление развертывания сохраняет резервные копии для текущей версии бинарного файла, `.env.example` и единицы systemd. Если развертывание файла или перезапуск завершается неудачно, `epctl` пытается восстановить файлы предыдущей версии.

### Изменения API {#api-changes-1}

- Админ, отвечающий за обработку платежей, принимает заявки на ожидание и истекшие заказы после проверки транзакций в блокчейне.
- `POST /pay/submit-tx-hash/{trade_id}`
- Документация настроек теперь рассматривает `rate.api_url` как необязательный параметр и описывает поведение по умолчанию для `rate.forced_rate_list`.

## v1.0.9 {#v1-0-9}

- Тег версии: `v1.0.9`
- Дата публикации: `2026-06-29T10:11:08Z`
- Официальное описание версии: `Full Changelog: https://github.com/GMWalletApp/epusdt/compare/v1.0.8...v1.0.9`

### Изменения для пользователей {#user-visible-changes-2}

- **Выбор типов EPay**: Сейчас скрипт submit.php EPay принимает либо `type=alipay`, либо поддерживаемый селектор типа `type=token.network`, например, `usdt.tron`.  Правильные селекторы выбирают платежный токен/сеть напрямую.
- При возврате покупателя и отправке уведомления EPay теперь передаёт сохранённый `type` из запроса, а не постоянное значение `alipay`.
- Процесс установки может возвращать исходный пароль администратора при первом запуске, в то время как открытый административный API теперь предоставляет только конечную точку для хэша исходного пароля для предупреждений в пользовательском интерфейсе.
- Добавлена исполняемая бинарная утилита Linux `epctl` для установки/управления, а также `epctl-docker-test.sh` для проведения комплексной проверки на основе Docker.

### Внесение изменений в развертывание и конфигурацию {#deployment-and-configuration-changes-2}

- `epctl` устанавливает выпущенные бинарные файлы в `/opt/epusdt`, создает файл `epusdt.service`, сохраняет существующий файл `/opt/epusdt/.env` при установке/обновлении, и может быть установлен глобально в `/usr/local/bin/epctl`.
- При допустимом значении `type=token.network` настройки EPay `epay.default_token` и `epay.default_network` игнорируются. Резервное значение валюты по-прежнему задаётся `epay.default_currency`.
- Не требуются новые переменные окружения.

### Изменения API {#api-changes-2}

- `GET` / `POST /payments/epay/v1/order/create-transaction/submit.php` теперь ограничивает поле `type` для непустых значений только `alipay` или текущим поддерживаемым селектором `token.network`.
- Маршрут `GET /pay/return/{trade_id}` и асинхронные уведомления EPay используют сохранённый `type`. Если `type` отсутствует, используется `alipay`.
- `GET /admin/api/v1/auth/init-password-hash` остается конечной точкой для первоначального хеша пароля; старый административный маршрут `init-password` не зарегистрирован в этой версии.

## v1.0.7 {#v1-0-7}

- Тег версии: `v1.0.7`
- Дата публикации: `2026-06-16T11:37:43Z`
- Официальное описание версии: `Full Changelog: https://github.com/GMWalletApp/epusdt/compare/v1.0.6...v1.0.7`

### Изменения для пользователей {#user-visible-changes-4}

- Концовки создания заказов в GMPay и EPay теперь поддерживают заказы-заполнители — заказы могут быть созданы без необходимости немедленно указывать адрес для оплаты в блокчейне, что позволяет интегрироваться с системами, которым нужны идентификаторы заказов до выбора фактического способа оплаты.
- Запросы-заполнители преобразуются в полные заказы, осуществляемые непосредственно в блокчейне, когда клиент выбирает платежную сеть в процессе оплаты.
- Текущий рабочий процесс теперь поддерживает отложенный выбор сети, позволяя торговцам создавать заказы, а затем давать клиентам возможность выбирать способ оплаты.

### Внесение изменений в развертывание и конфигурацию {#deployment-and-configuration-changes-4}

- Не требуются новые переменные окружения.
- Поддержка "заполнителя" включена по умолчанию для процессов GMPay и EPay.

### Изменения API {#api-changes-4}

- `POST /payments/gmpay/v1/order/create-transaction` и конечные точки создания заказов EPay теперь принимают заказы без необходимости указывать параметры `network` или `token` на первом этапе — отсутствие этих параметров создает заполнительный заказ.
- Заявки-заполнители возвращают `trade_id` и ссылку на кассира, но не содержат адрес кошелька до тех пор, пока клиент не выберет сеть.
- `POST /pay/switch-network` преобразует зарезервированный заказ в полноценный заказ, осуществляемый на блокчейне, путем назначения выбранной сети и генерации адреса для оплаты.
