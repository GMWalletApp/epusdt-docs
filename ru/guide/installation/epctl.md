# Скрипты установки и проверки epctl {#epctl-installation-and-verification-scripts}

`epctl` — это утилита для установки и управления сервисами для бинарных файлов `epusdt`, выпущенных на GitHub Releases.
`epctl-docker-test.sh` — это скрипт для комплексной проверки. Он запускает Ubuntu + systemd в Docker и проверяет поведение при загрузке, установке, запуске, обновлении и инициализации паролей с использованием реальных артефактов.

Для новой установки сначала скачайте файлы нужной версии.

```sh
git clone --depth 1 --branch v2.1.1 https://github.com/GMWalletApp/epusdt.git
cd epusdt
```

## Область применения {#scope}

- Только Linux
- Только установка готовых бинарных файлов
- Источник для публикации зафиксирован по адресу: `https://github.com/GMWalletApp/epusdt/releases`
- Управление сервисами основано на systemd

## Зависимости и привилегии {#dependencies-and-privileges}

`epctl` ожидает следующие команды:

- `curl`
- `tar`
- `systemctl`
- `install`
- `grep`
- `sed`

Примечания

- Команды `install`, `upgrade` и `self-install` записывают файлы в `/opt`, `/etc/systemd` и `/usr/local/bin`.
- `status` и `logs` автоматически запускаются повторно через `sudo` при необходимости.
- В практическом применении, оператору необходимо иметь доступ с правами `sudo`.

## Фиксированные пути {#fixed-paths}

| Элемент | Путь |
|------|------|
| Каталог установки | `/opt/epusdt` |
| Основной исполняемый файл | `/opt/epusdt/epusdt` |
| Исполняемый файл сканера | `/opt/epusdt/chainscanner` |
| Действующий файл конфигурации | `/opt/epusdt/.env` |
| Файл настроек сканера | `/opt/epusdt/chainscanner.json` |
| Пример конфигурации | `/opt/epusdt/.env.example` |
| Извлеченные ресурсы фронтенда | `/opt/epusdt/www` |
| Кеш загрузок | `/tmp/epusdt/<tag>/` |
| Юнит systemd | `/etc/systemd/system/epusdt.service`, `/etc/systemd/system/chainscanner.service` |
| Глобальный путь к epctl | `/usr/local/bin/epctl` |

## Быстрый старт {#quick-start}

Запустите интерактивное меню из корня репозитория.

```bash
./epctl
```

По умолчанию языком для взаимодействия является китайский. Вы можете установить любой язык:

```bash
./epctl zh
./epctl en
./epctl --lang zh help
./epctl --lang en help
```

Установите скрипт в PATH:

```bash
./epctl self-install
epctl
```

## Основные команды {#common-commands}

Скачать конкретную версию.

```bash
./epctl download --tag v2.1.0
```

Установите сервис (по умолчанию `--component epusdt` с встроенным сканером). Используйте `--component all` для двух отдельных сервисов.

```bash
./epctl install --tag v2.1.0 \
  --app-uri https://pay.example.com \
  --listen 127.0.0.1:18000
```

Разверните `chainscanner` в автономном режиме (автоматически генерирует токены или принимает их и выводит учетные данные для подключения).

```bash
./epctl install --component chainscanner \
  --scanner-listen 0.0.0.0:9081
```

Развернуть `epusdt` в автономном режиме (подключение к удаленному `chainscanner`).

```bash
./epctl install --component epusdt \
  --app-uri https://pay.example.com \
  --listen 127.0.0.1:8000 \
  --scanner-url http://10.0.0.2:9081 \
  --scanner-token <chainscanner_token> \
  --scanner-admin-token <chainscanner_admin_token>
```

Обновите до более новой версии (автоматически определяет установленные компоненты, или укажите `--component all|epusdt|chainscanner`).

```bash
./epctl upgrade --tag v2.1.0
```

Выполнение `./epctl upgrade --tag ...` напрямую перезапускает `epusdt` сразу после замены файлов.
Если вы хотите заменить только файлы, используйте опцию `--no-restart`.
Если вам требуется дополнительный шаг подтверждения, используйте опцию `--prompt-restart`. В интерактивной консоли подсказка – `[Y/n]`, поэтому нажатие Enter по умолчанию перезапускает процесс.

Проверьте конфигурацию, статус и логи.

```bash
./epctl show-config
./epctl status
./epctl logs --lines 200
```

Запросите первоначальный пароль администратора.

```bash
./epctl init-password
```

## Поведение при отсутствии тега `--tag` {#behavior-when-tag-is-omitted}

Для команд `download`, `install` и `upgrade` инструмент `epctl` сначала определяет актуальный тег релиза на GitHub, затем показывает его и запрашивает подтверждение.

Пример

```bash
./epctl install --app-uri https://pay.example.com
```

В режиме интерактивного использования, скрипт будет отображать самый последний примененный тег перед продолжением.
Для автоматизации рекомендуется использовать опцию `--tag` явно. Если вы намеренно хотите пропустить подтверждение, используйте:

```bash
EPCTL_ASSUME_YES=1 ./epctl download
```

## Что происходит при первой установке {#what-happens-on-first-install}

Команда `install` выполняет следующие действия:

1. Определите текущую архитектуру процессора и скачайте соответствующую архиву GitHub Release.
2. Извлечь в `/tmp/epusdt/<tag>/extract/`
3. Установите бинарные файлы в `/opt/epusdt/epusdt`
4. Установите файл `.env.example` в `/opt/epusdt/.env.example`
5. Создайте пользователя и группу в системе `epusdt`.
6. Создать файл `/opt/epusdt/.env` автоматически из `.env.example`, если он не существует.
7. Напишите и включите `epusdt.service`.

Когда файл `.env` создается автоматически, скрипт применяет только минимальные изменения для настройки.

- `install=false`
- `app_uri=<--app-uri, default http://127.0.0.1:8000>`
- `http_listen=<--listen, default 127.0.0.1:8000>`

Если файл `/opt/epusdt/.env` уже существует, установите и обновите его без изменений.
Файл `/opt/epusdt/.env.example` обновляется с текущей версией при каждой установке / обновлении.

## Что происходит во время обновления {#what-happens-during-upgrade}

Команда `upgrade` выполняет следующие действия:

1. Определите текущую архитектуру процессора и скачайте архив с релизом из GitHub.
2. Извлечь в `/tmp/epusdt/<tag>/extract/`
3. Требуется наличие файла `/opt/epusdt/.env`. Если его нет, команда завершится неудачно и сообщит вам, что необходимо сначала запустить `install`.
4. Заменить `/opt/epusdt/epusdt`
5. Заменить `/opt/epusdt/.env.example`
6. Сохраните существующий `/opt/epusdt/.env`
7. Обновите службу `epusdt.service` и выполните `systemctl daemon-reload`
8. Немедленно перезапустить `epusdt` по умолчанию.

Дополнительные особенности

- Команда `upgrade` больше не создаёт `.env` и не выполняет `systemctl enable`.
- `upgrade --no-restart` заменяет файлы только и выводит предупреждение о необходимости ручного перезапуска.
- `upgrade --prompt-restart` спрашивает, следует ли перезагружать систему, если доступен интерактивный терминал.
- Если перезагрузка не удалась после обновления, скрипт пытается откатить предыдущую версию файла `.env.example` и файл с единицами.

## Параметры службы systemd {#systemd-service-details}

Название сервиса зафиксировано как `epusdt.service` и использует следующие основные настройки:

```ini
WorkingDirectory=/opt/epusdt
ExecStart=/opt/epusdt/epusdt http start
User=epusdt
Group=epusdt
Restart=always
RestartSec=3
```

Рабочая директория остается на `/opt/epusdt`, так как программа извлекает свои ресурсы `www/` рядом с бинарным файлом.

## Что такое `init-password` {#what-init-password-does}

`epctl init-password` вызывает только локальный HTTP-маршрут.

```text
GET /admin/api/v1/auth/init-password
```

Оно не читает базу данных напрямую.

Скрипт считывает `http_listen` из `/opt/epusdt/.env` и нормализует эти значения прослушивания для получения локального целевого адреса запроса:

- `:8000` -> `127.0.0.1:8000`
- `0.0.0.0:8000` -> `127.0.0.1:8000`

Если API возвращает `10040`, то исходный пароль для инициализации больше недоступен. Распространенные причины:

- Пароль администратора уже был изменен.
- Первоначальный пароль уже использован и его невозможно получить повторно.

В таком случае, `epctl` выводит исходное тело HTTP-ошибки для диагностики.

## Проверочный скрипт Docker {#docker-validation-script}

Репозиторий также содержит:

```bash
./epctl-docker-test.sh <install-tag> [upgrade-tag]
```

Примеры

```bash
./epctl-docker-test.sh v2.1.0
./epctl-docker-test.sh --lang en v2.0.0 v2.1.0
```

Оно выполняет эти проверки на локальном компьютере:

- Начинается непосредственно из образа `ubuntu:24.04` и устанавливает systemd, а также необходимые зависимости для контейнера на этапе инициализации.
- запускает привилегированный контейнер
- выполняет команду `epctl self-install` внутри контейнера
- Скачать реальные артефакты с GitHub Release
- Установка `epusdt`
- Если указан `upgrade-tag`, проверяются `upgrade --no-restart`, обычный неинтерактивный `upgrade` и оба варианта ответа на `upgrade --prompt-restart`: `n` и Enter.
- проверяет службу systemd, `www/index.html`, конфигурационный вывод, логи и статус
- проверяет, что `init-password` успешно выполняется один раз, а затем возвращает `10040` после изменения административного пароля

Требования

- Локально установленный Docker
- Разрешение на запуск Docker
- Доступ к GitHub Releases (наружу)

## Рекомендации {#recommendations}

- Предпочитайте явные значения `--tag` в автоматизации.
- После установки, запустите `./epctl show-config` один раз, чтобы проверить, что активен `.env`.
- Немедленно измените пароль администратора сразу после получения исходного пароля.
- Если вы хотите проверить установщик, сначала запустите `./epctl-docker-test.sh`.
