## API администрирования {#admin-api-surface}

API для управления находятся по адресу `/admin/api/v1/*`, и защищены с помощью JWT, за исключением конечных точек для входа и первоначальной установки пароля.

Ключевые группы, видимые в текущем источнике:

- Публичный кассир принимает хэш для ожидающего транзакционного заказа. Администратор также может проверить истекший заказ или заявку в ручном режиме.
- Настройка `rate.mode` принимает `fixed` или `auto`. Фиксированный режим использует `rate.forced_rate_list`. Автоматический получает курсы из `rate.api_url`, кеширует успешные ответы по базовым валютам и при сбое обновления сохраняет последний постоянный кеш. Пустой `rate.forced_rate_list` восстанавливает встроенные курсы CNY для USDT/USDC.
- `/auth/*`
- `/api-keys/*`
- `/notification-channels/*`
- `/config`
- управление цепочками / токенами
- управление адресами кошельков

## Правила, касающиеся профессиональных лицензий торговцев {#merchant-credential-rules}

### GMPay {#gmpay}

- Необходимый идентификатор продавца: `pid`
- Поле подписи: `signature`
- Алгоритм подписи начиная с версии `v2.0.0`: HMAC-SHA256 с использованием канонической строки параметров, не содержащей пробелов, зашифрованная ключом `api_keys.secret_key`, соответствующим `pid`.
- Клиенты Pre-v2 GMPay MD5 должны быть обновлены перед внедрением `v2.0.0` или более поздних версий.

### Сценарий оплаты через EPay {#epay-compatible-flow}

- Необходимый идентификатор продавца: `pid`
- Поле подписи: `sign`
- Ключ подписи: `secret_key` соответствующей включенной строки `api_keys`, которая соответствует `pid`.
- `sign_type` обычно принимается, и часто используется `MD5`.
- Поле EPay `type` принимает `alipay` или поддерживаемый селектор `token.network`, например `usdt.tron`. Принятое значение сохраняется при возврате покупателя и в уведомлениях EPay.

## Рекомендуемый порядок интеграции {#recommended-integration-order}

1. Создайте или проверьте данные учетных записей торговцев в панели администратора (`pid` + `secret_key`)
2. Запрос `/payments/gmpay/v1/config` и чтение `data.supported_assets`, если клиенту требуются динамические сетевые/токенные опции.
3. Для новых интеграций рекомендуется GMPay
4. Используйте перенаправление, совместимое с EPay, только тогда, когда система, находящаяся выше в цепочке, ожидает этого процесса.
5. Проверьте обратные вызовы с тем же продавцом, используя `secret_key`.
